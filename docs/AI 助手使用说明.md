# BTC 指示器 · AI 助手（千问）使用说明

> 一句话：**把页面上已有的所有行情数据拍成一张"快照"塞给千问，让它基于真实数字给涨跌判断，而不是让它去猜。**

---

## 1. 五分钟上手

1. **拿 Key**：到 [阿里云百炼](https://bailian.console.aliyun.com/) 控制台 → 「API-KEY 管理」→ 创建。Token Plan 个人版的 Key 在「我的订阅」页面生成，形如 `sk-sp-...`，只完整显示一次。
2. **填 Key**：打开本页面 → 右上角「API 接入中心」→ 「AI 大模型」分组 → 千问 Qwen 卡片 → 粘贴 Key → 选模型（默认性价比档 `qwen3.8-flash`）→ 保存 → 「验证 Key」确认绿标。
3. **问问题**：页面紫色「AI 助手」悬浮按钮（默认在右下角，**可随意拖到页面任何位置**）→ 在对话窗提问，或直接点快捷芯片。回答按【结论】【为什么这么判断】【关键价位】【什么情况说明我判断错了】【风险提醒】五段渲染；语气默认「通俗」，可在右上角切换为「中等 / 专业」。

**悬浮按钮与对话窗的几件事：**

| 行为 | 说明 |
|------|------|
| 按钮动效 | 外发光呼吸（紫↔青）+ 双层波纹向外扩散 + 圆点变色跳动，始终可见；首次打开后只收敛一档（波纹更慢更淡），不会静默 |
| 拖动按钮 | 按住按钮拖到任意位置，位置记在本机浏览器；**已打开的对话窗会立即跟着贴过去** |
| 打开位置 | 对话窗**紧贴按钮**弹出：优先贴按钮正上／正下方并与按钮左缘或右缘对齐；纵向放不下时改为贴着按钮左右并排，都放不下才夹进视口 |
| 缩放窗口 | 拖四条边框单独拉伸宽／高，拖四个角同时改宽高，最小 320×340，尺寸记在本机 |
| 收起窗口 | 点页面空白处、点右上角「关闭」或按 `Esc` 都可以收起；再次点按钮重新打开 |

对话框右上角有两个**互不影响**的选择器：

| 徽标 | 控制什么 | 选项 |
|------|---------|------|
| `快速 / 深度` | 模型**想多久**（是否保留推理） | 快速（默认）/ 深度 |
| `通俗 / 中等 / 专业` | 说给**谁听**（术语密度与语气） | 通俗（默认）/ 中等 / 专业 |

### 1.1 思考模式：快速 / 深度（对话框右上角「快速」徽标）

| 模式 | 耗时实测 | 说明 |
|------|---------|------|
| **快速**（默认） | **约 20 秒** | 关闭模型思考（`enable_thinking: false`），直接给结论。日常看盘够用 |
| **深度** | 约 55 秒 | 保留推理过程并限制长度（`thinking_budget: 4096`），更审慎，适合重要决策前 |

> 两者对比：不设限的思考模式原本要 **75-105 秒**。快速模式省掉推理直接回答，深度模式压缩推理长度，都在保质量的前提下把等待砍掉一大半。模式选择会记在浏览器本地。

### 1.2 回答模式：通俗 / 中等 / 专业（对话框右上角「通俗」徽标）

同一份数据、同一套事实约束，只换**讲法**。三档用不同的系统提示词，切档对下一条提问立即生效，选择同样记在浏览器本地。

| 档位 | 给谁看 | 提示词差异 |
|------|--------|-----------|
| **通俗**（默认） | 完全不懂技术分析的人 | 不用任何术语（RSI 说成"衡量抢着买还是抢着卖的指标"），支撑叫"地板"、阻力叫"天花板"，禁止出现字段名，必须提指标时先白话再括号解释 |
| **中等** | 懂一点但不深的人 | 术语可以用，但**首次出现配一句白话解释**；保留少量形象说法，关键数字必须说明相对现价的含义与距离 |
| **专业** | 熟悉技术分析的人 | 术语与读数直接给（EMA20、RSI14、MACD 柱、布林带宽、ATR14、资金费率与基差符号量级），日线/4H/1H 分周期陈述并点明共振或背离，要求"若 X 则 Y"的条件化结论 + 主/次情景概率，禁止白话解释与生活比喻 |

三档都共用同一条底线：只用快照里的真实数据（缺失就直说，不许猜）、观点必须可验证（给具体价格或条件）、不承诺收益、不写"综上所述"这类填充句。

**注意**：切档只改语气，不改结论质量。想要更深的多空权衡，请同时把思考模式切到「深度」。

整套流程浏览器**永远不会拿到你的 Key** —— Key 通过 AES-256-GCM 加密保存在 `data/api-credentials.json`（权限 600），只有 8787 服务进程能解密后调用千问。

### 1.3 持仓上下文：AI 知道你的仓位（自动，无需设置）

只要你在顶部持仓卡里填了开仓价 / 持仓量 / 保证金 / 杠杆，每次提问时对话窗会**自动**附带：

- **你的持仓**：方向、开仓价、持仓量、保证金、杠杆。服务端会用当前价**替你算好**浮动盈亏、保证金回报（ROE）、理论强平价和距强平的百分比，AI 直接引用这些现成结论，不会自己算错。
- **页面信号面板**：规则信号卡（如「做空 -50.00」）与「方向研究估算」的原文。AI 会引用它们，但会和行情快照交叉验证，发现矛盾会指出。

效果示例（专业档，测试持仓：35x 多单 / 开仓 78,550）：

> 强平参考价：76,698（用户持仓理论强平价）……你持有 35x 高杠杆多单，当前浮亏 -65.29%，距离强平线仅 -0.5%。任何跌破 76,900 的微小下跌都可能直接导致爆仓。

几点说明：

- 快照同时新增了 **5 分钟周期**（1d / 4h / 1h / 5m 四档），与页面信号基准周期对齐。
- **持仓数据只发给千问 API**（阿里云），仅含几个价格数字，不含任何账户身份信息；不填持仓卡就什么都不发，AI 也不会虚构仓位。
- 不想让自己仓位参与分析时，清空持仓卡再提问即可。

Token Plan 个人版「支持模型」面板里列了 7 个型号，其中 5 个能用于行情问答：

| 模型 | 档位 | 官方单价（输入/输出，元/百万 token） | 一句话 |
|------|------|--------------------------------|--------|

## 2. 三件事怎么做的（对应你的三个问题）

### 2.1 数据是怎么获取的

不是让千问自己上网查，而是由 `server.mjs` 内置的同一套数据层（与页面顶部展示的 K 线/指标完全同源）在每次提问时聚合成一份快照：

| 维度 | 数据来源（与页面同源） | 加工方式 |
|------|----------------------|---------|
| 1d / 4h / 1h K 线 | `market(interval, 240, source)` 走 OKX/Coinbase/Binance/Gate 多源降级 | 各周期取最近 45 / 36 / 18 根 OHLCV 紧凑数组 |
| 技术指标 | `ai-chat.mjs` 自带的纯 JS 计算（EMA20/50/200、RSI14、Wilder 平滑、MACD line/signal/histogram、Bollinger 20±2σ、ATR14、波动率、量能比、**多空打分**） | 由 K 线现场计算，**不依赖前端** |
| 衍生品 | `marketContext()` → 资金费率、下期费率、持仓量、期现基差、OKX WebSocket 优先 | 与页面「市场环境」卡片完全一致 |
| 情绪 | `fearGreedSentiment()` → Alternative.me 恐慌贪婪指数 | 与页面「恐慌贪婪」卡片完全一致 |
| 宏观 | `fedMonitor()` + `investmentCalendar()` → FOMC / CPI / 非农 / 国债拍卖等 | 按 `events` 字段优先选取，避免误抓 `marketSignals` |
| 多周期共振 | 各周期多空打分求和（范围 ±18） | 自带逻辑 |

整张快照约 **2.4 KB / 750 字符 ≈ 2400 token**（含 K 线），远低于千问 32K/256K/1M 上下文，提问时是「快照 + 你的问题 + 最近 8 轮对话」一起发。同一个问题并发只会抓一次快照（20 秒内复用缓存）。

### 2.2 MCP 服务器

`mcp-server.mjs` 是一个**零依赖的 stdio JSON-RPC 2.0** 服务，它把上面那张快照拆成 5 个工具给外部 AI 客户端（WorkBuddy、Claude Desktop 等）调用：

| 工具 | 作用 |
|------|------|
| `get_market_snapshot` | 一次拿全（≈2.4KB） |
| `get_price` | 只要当前价 + 24h 涨跌 |
| `get_indicators(timeframe?)` | 单周期画像（1d/4h/1h） |
| `get_sentiment` | 恐惧贪婪 + 资金费率 |
| `get_macro_calendar` | 即将公布的宏观事件 |

**配置**（已写入 `~/.workbuddy/mcp.json`）：

```json
"btc-indicator": {
  "command": "/Users/jeffereyreng/.local/share/mise/installs/node/26/bin/node",
  "args": ["/Users/jeffereyreng/ChatGPT/btc指示器/mcp-server.mjs"]
}
```

> 改完 MCP 配置需要**重启 WorkBuddy**，再到连接器面板里点「Trust」才生效。前提是本地 8787 看板服务在跑（这条服务是看板的薄封装，不重复采集）。

### 2.3 数据怎么发给千问

服务端组装好 `system` 消息（回答模式提示词 + 实时快照 + 深度模式补充）+ 你的对话历史，POST 到 DashScope 的 OpenAI 兼容接口：

```
POST https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions
Authorization: Bearer <你的 Key>
Content-Type: application/json

{
  "model": "qwen3.8-flash",
  "stream": true,
  "temperature": 0.7,          // 快速模式；深度模式用 0.6
  "top_p": 0.8,                // 快速模式；深度模式用 0.95
  "max_tokens": 1400,          // 快速模式；深度模式给 5500（要留推理余量）
  "enable_thinking": false,    // 快速模式；深度模式为 true + thinking_budget 4096
  "messages": [
    { "role": "system", "content": "<按所选回答模式取用的提示词>" },
    { "role": "system", "content": "以下是生成于 ... 的实时市场快照：\n\n{ ... JSON ... }" },
    { "role": "system", "content": "本次是「深度分析」模式 ..." },   // 仅深度模式追加
    { "role": "user", "content": "现在能追多吗？" }
  ]
}
```

`style` 参数在服务端经**白名单校验**（`normalizeStyle`），只接受 `plain` / `balanced` / `pro`，其他值一律落回 `plain`，不会把任意字符串拼进提示词。提示词模板在 `ai-chat.mjs` 的 `STYLE_PROMPTS` 里，三档分别维护。

**为什么是 OpenAI 兼容接口**：DashScope `compatible-mode/v1/chat/completions` 完全兼容 OpenAI 协议，可以零成本切换到 OpenAI / DeepSeek / 智谱等同协议服务（只改 `baseUrl` + `model` 即可）。如果你用新加坡地域，把 `baseUrl` 改成 `https://dashscope-intl.aliyuncs.com/compatible-mode/v1` 即可。

**为什么用结构化 JSON 而非自然语言喂数据**：模型对"比特币现在 78100，4h 周期 MACD 死叉…"这种自然语言容易丢精度/改数。给它纯 JSON 数值 + 明确的字段名，它反而不会幻觉。

**输出契约**（在 system prompt 里写死，三档共用同一组小标题）：

- 【结论】短期更可能涨 / 跌 / 震荡 + 概率感觉
- 【为什么这么判断】2-4 条依据，必须引用快照里的具体数值
- 【关键价位】支撑 / 阻力具体价格 + 相对现价的距离
- 【什么情况说明我判断错了】可验证的失效价格或条件
- 【风险提醒】一句话杠杆与波动提示

非行情类问题（"什么是资金费率"等）模型会自动跳出这个结构，自由回答。

**流式响应**：服务端把 DashScope 的 SSE 增量原样转给浏览器（`text/event-stream`），前端用 `ReadableStream` 逐块追加到同一条消息上 —— 体验是打字机效果。深度模式下上游的 `reasoning_content` 只转成"已推理 N 字"的进度提示，不把推理正文给用户看。

## 3. 路由与限流

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/ai/config` | GET | 返回 `{ configured, model, defaultModel, baseUrl, models, endpoints, thinkingModes, answerStyles, defaultStyle, snapshotTtlMs }` |
| `/api/ai/snapshot` | GET | 仅返回当前快照（调试用） |
| `/api/ai/quota` | GET | 返回额度状态：`remote`（响应头）+ `local`（本地累计）+ `note` |
| `/api/ai/model` | PUT | 切换模型；body `{ model }`。**只改模型名**，Key 与端点不动，无需重新验证 |
| `/api/ai/chat` | POST | 提问；body `{ question, history?, stream?, source?, lang?, thinking?, style? }`。`thinking` 取 `fast`/`deep`，`style` 取 `plain`/`balanced`/`pro` |
| `/api/api-center` | GET/PUT/DELETE | 已在原有 API 接入中心里扩了 `qwen` provider（key+baseUrl+model 三件套） |
| `/api/api-center/verify` | POST | 用一次极小 chat 请求验证 Key + 端点 + 模型是否匹配 |

### 3.1 额度面板

对话窗顶部固定一条额度进度条，API 接入中心千问卡片里也有一张 mini 卡。它们共用 `/api/ai/quota`，每 60 秒轮询一次，每次成功问答后立即刷新。

本地累计会**落盘到 `data/ai-quota.json`**，服务重启后不会归零（早期版本是纯内存态，重启一次已用量就倒退，已修）。文件里只存 tokens/credits 计数与最近 50 次调用记录，不含任何密钥。计费周期结束时（Token Plan 的 7 天窗口）会自动清零重新起算。

显示内容：

- **进度条 + 剩余百分比**：绿色（>50%）/ 黄色（>20%）/ 红色（≤20%）
- **剩余 / 总额度**（如有响应头最准，否则本地估算）
- **重置时间 + 倒计时**（如「09-17 18:05 · 6d 23h」）
- **累计调用次数与 tokens**（含思考 tokens）
- **最近 10 次调用明细**（点击进度条展开）

> **关于精度**：阿里云百炼的 OpenAI 兼容端点**不返回** `x-ratelimit-*` 响应头，所以「精确剩余 credits」服务端拿不到。本地按模型换算表估算：例如 `qwen3.8-max` 约输入 2.5 / 输出 7.5 credits per 1k tokens，1 次典型问答约 30-50 credits。**与 Token Plan 控制台显示差值通常在 20% 以内**，如需精确请以控制台为准。

**本地保护**：
- 单 IP 令牌桶：12 容量 / 5 秒回血 1 个 —— 防误触烧钱
- 单次问题 2000 字符上限
- 30 秒上游超时
- body 128KB 限制
- 历史只保留最近 8 轮

## 4. 故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 提示「尚未配置千问 API Key」 | 还没在 API 接入中心保存 | 打开右上角 → AI 大模型卡片 → 填 Key → 保存 → 验证 |
| 验证 Key 时 401 | Key 错/过期/被撤销 | 重发 Key，注意 DashScope 控制台区分「北京」与「新加坡」地域 |
| 验证 Key 时 404 | 端点写错（少了 `/v1`，或错把 `/api/v1` 写了进来） | 端点应为 `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 验证 Key 时 400 `model not found` | 模型名拼错 | 从模型浮层里点选（如「qwen3.8-flash」）即可，不要手敲 |
| 切了语气档但回答没变 | 切档对**下一条**提问生效，已生成的历史回答不会重写 | 直接问下一个问题即可；确认右上角徽标已变成「中等 / 专业」 |
| 对话窗一直转圈 | 30s 还没回来 | 复杂问题快照大；可点关闭重开 |
| MCP 工具调用失败「看板服务未运行」 | 8787 没在监听 | `launchctl kickstart -k gui/$(id -u)/com.jeffereyreng.btc-indicator` |

## 5. 更换模型或供应商

**换千问模型**：点对话框右上角模型徽标，或在「API 接入中心 → 千问卡片 → 模型」下拉里选。可选项就是 Token Plan 个人版「支持模型」面板列出的全部型号（文本类可切，图片/语音类置灰）。

切换走 `PUT /api/ai/model`，**只重写模型名**：Key 与端点原样保留，不需要重新验证，也不会清掉已验证状态。

**换供应商**（DeepSeek、OpenAI、智谱等 OpenAI 兼容厂商）：协议层不用改 —— 服务端只依赖 `Authorization: Bearer` 头 + OpenAI 的 `chat/completions` 格式，不绑定具体厂商。但有两处要在 `ai-chat.mjs` 里补：

1. **模型清单**：`QWEN_MODELS` 里加一行，否则接口会拒绝未登记的型号——
   ```js
   { id:'deepseek-chat', label:'deepseek-chat', tier:'balanced', note:'第三方：按量计费', usable:true }
   ```
2. **credits 换算**：`MODEL_CREDITS_PER_1K` 里加对应行，否则估算会回退到 qwen3.8-max 的费率（数值偏高，仅影响显示，不影响实际扣费）。
