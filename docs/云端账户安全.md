# 云端账户与 API 设置安全说明

## 保护范围

- 云端账户的两笔持仓资料（开仓价、持仓量、保证金、杠杆及方向）写入 PostgreSQL 前，使用 AES-256-GCM 加密。
- Server酱 SendKey 使用同一算法加密；Redis 队列只保存规则、价格和用户标识，工作进程投递前才从数据库短暂解密。
- API 中心的内置 Key、手动填入的 HTTPS API 地址及其可选 Key 写入 `data/api-credentials.json` 前，使用 AES-256-GCM 加密。浏览器只会收到已保存状态，不会收到原文。
- 本机规则、SendKey 和用户主动保存过的 API 配置使用浏览器 Web Crypto 的 AES-256-GCM 加密后存入 IndexedDB；加密密钥为不可导出的 `CryptoKey`，不写入 `localStorage`。退出登录时可选择保留或清除该本机密文副本；旧版明文 `localStorage` 会迁移后删除。

每个 AES-GCM 密文均有随机 96 位 IV 和 128 位认证标签。云端账户记录还使用附加认证数据绑定 `用户 ID + 数据用途`；把一条密文拷贝到另一用户或字段会验证失败。加密密钥由 `ALERT_ENCRYPTION_KEY` 或单独的 `API_CREDENTIAL_ENCRYPTION_KEY` 从环境变量/部署密钥管理器注入，绝不写入前端、镜像或仓库。

## 部署

用下列命令生成密钥，并将值保存到部署平台的 Secret/KMS 或未提交的 `.env`：

```sh
openssl rand -base64 32
```

生产环境必须通过 Caddy 的 HTTPS 域名访问。账户 API 拒绝非 HTTPS 请求（开发时仅允许 localhost）；会话 Cookie 使用 `HttpOnly`、`SameSite=Strict` 和生产环境的 `Secure` 标记。Caddy 同时发送 HSTS。

旧版持仓 JSONB 在用户下次读取资料时会自动加密迁移，并把原 JSONB 清为空对象。旧版 API 设置文件在可用加密密钥存在时于服务启动时迁移。迁移前应备份数据库与 `data/` 目录。

## 校验与错误处理

手动 API 和内置 API 使用同一服务端写入路径：Key 最大 512 字符；手动地址必须为不带用户名/密码的 HTTPS URL、最长 2048 字符。空值、非法地址、未登录、缺少密钥、解密认证失败和上游请求失败都会返回明确错误，前端以弹窗展示。地址与 Key 均不回显。

## 局限与密钥轮换

AES-256-GCM 能保护静态存储和检测篡改，但不能抵抗已控制应用服务器、运行时内存或密钥管理器的攻击；HTTPS 只能保护传输链路，不能保护用户终端已被攻陷的情况。请把密钥放在受访问控制的 Secret/KMS，限制数据库/Redis 网络访问，并定期轮换。

浏览器端不可导出密钥可防止磁盘、浏览器存储导出和普通备份直接读出明文，但同源恶意脚本或已解锁的浏览器会话仍可能调用该密钥执行解密。因此仍需保持 CSP、依赖审计和设备安全；不要把浏览器本地加密当作替代端到端密码学的方案。

当前实现支持旧版兼容读取，但不会自动使用新密钥重加密已有 `v1` 密文。轮换时应在维护窗口内使用旧密钥读取、用新密钥重写所有资料与 SendKey，再撤销旧密钥；否则历史密文会不可恢复。
