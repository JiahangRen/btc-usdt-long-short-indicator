# 前端渲染架构

本项目继续使用原生浏览器脚本，以确保现有页面的文字、卡片顺序和交互完全不变。

## 文件职责

- `public/index.html`：静态页面骨架与脚本加载顺序。
- `public/core/panel-registry.js`：面板 id、信息层级与默认展开状态的唯一登记处；当前只登记、不移动 DOM。
- `public/app.js`：行情、图表、指标、研究卡片及本地工具的兼容实现。
- `public/styles.css`：现有视觉样式；尚未进行会改变级联顺序的大规模拆分。

## 统一渲染入口

- `renderChart()`：图表重绘的唯一公共入口，`draw()` 仅保留兼容别名。
- `renderDecisionPanels()`：决策层公共入口。
- `renderAnalysisComposed()`：基础分析渲染器加有序 `decisionRenderEnhancers` 队列。
- `renderFixedRuleSignal()`：基础固定规则信号渲染器加有序 `fixedRuleSignalEnhancers` 队列。
- `renderExpandedIndicatorDetails()`：基础指标详情渲染器加有序 `indicatorDetailEnhancers` 队列。

## 增强步骤原则

新增展示逻辑不得再使用 `const old = render; render = function () { old(); ... }`。
应使用对应的 `add…Enhancer(id, render)` 注册，并保持：

1. id 唯一；
2. 依赖前置 DOM 的步骤排在其后；
3. 不在步骤中移动无关卡片；
4. 对可选数据和未挂载 DOM 使用安全返回。

## 布局迁移原则

`BTCPanels` 已登记现有面板的 tier，但当前不重排节点，以满足“前端可见内容不变”。后续若明确允许调整信息架构，再由 registry 统一执行插入与折叠；禁止继续通过跨模块 `insertBefore` 互相寻找锚点。
