# 研究预测模块审查 v2 · 三分类验证 + 宏观因子

> 定位修正：本模块是**多因子研究与验证平台**（验证 15m / 1h / 4h / 1d 的偏多 / 偏空 / 中性震荡判断，并与实时数据逐笔对比），**不是交易执行系统**。
> 因此 v1 报告里以「成本后净收益 / 最大回撤」为核心的评价体系需要整体降级，核心指标改为**三分类准确率 + 校准 + 与基线的差值**。
> v1 报告见 `docs/研究预测模块审查-20260920.md`；本文记录 v2 定位下的新增断点与修复顺序。

---

## 一、三分类（偏多 / 偏空 / 中性震荡）：目前无法验证

### 1.1 实测：绝大多数预测落在「震荡」，而评估体系只认涨/跌

| 周期 | 预测为 up | 预测为 flat | 预测为 down | flat 占比 |
|---|---|---|---|---|
| 15m | 9 | 351 | 18 | **92.9%** |
| 1h | 56 | 303 | 19 | **80.2%** |
| 4h | 83 | 264 | 31 | **69.8%** |

而结算标签 `is_up` 只有 0 / 1（`server.mjs:2124`，`isUp = actualReturn > 0 ? 1 : 0`）：
这 92.9% 的「震荡」预测在现有口径下被随机判成「涨对了 / 跌错了」（15m flat 中 188 条 is_up=1、162 条 is_up=0）。
**结论：你最想验证的那一类，恰恰是现在完全没有验证口径的那一类。**

### 1.2 训练阶段同样把震荡丢进了二分类

`trainFusionModel` 的三重屏障（`server.mjs:2050-2055`）：

```js
if (up !== down) return { y: up ? 1 : 0, event: up?'upper':'lower' };
return { y: closes[end] >= entry ? 1 : 0, event:'vertical' };   // ← 未触屏障，强制二值化
```

实测（coinbase 15m K 线，2563 个样本）：

| 周期 | upper | lower | **vertical（实为震荡）** | 屏障触及率 |
|---|---|---|---|---|
| 15m | 520 | 526 | **1517（59%）** | 22.9% |
| 1h | 612 | 628 | **1355（52%）** | 23.2% |
| 4h | 668 | 678 | **1231（48%）** | 24.1% |

近半数到六成样本本质是震荡，却被当成方向样本训练 → 模型学到的最优解就是「输出接近 0.5 的常数」，这正是 `mean|p−0.5|` 只有 0.030 / 0.037 / 0.048 的原因。

### 1.3 三分类口径下的真实表现（θ = 屏障宽度 1.15σ）

用 `|实际收益| ≤ θ` 定义震荡（θ：15m 0.192%、1h 0.384%、4h 0.770%），重新评估已结算样本：

| 周期 | 模型准确率 | 永远猜震荡 | 按实际频率随机猜 | 差值（模型 − 永远猜震荡） |
|---|---|---|---|---|
| 15m | 69.6% | 73.3% | 57.3% | **−3.7pp** |
| 1h | 61.8% | 76.7% | 61.6% | **−14.9pp** |
| 4h | 58.1% | 82.5% | 69.6% | **−24.4pp**（且低于随机 11.5pp） |

混淆矩阵（行 = 预测，列 = 实际）：

```
15m        up   flat  down      1h        up   flat  down      4h        up   flat  down
  up        4     4     1        up        6    45     5        up        5    70     5
  flat     52   258    41        flat     43   227    32        flat     27   209    25
  down      2    15     1        down      2    17     0        down      1    28     2
```

- 判为「震荡」但**实际走出趋势**的漏报率：15m 26.5%、1h 24.8%、4h 19.9%。
- 4h 的方向判断是**负价值**：不如一直说「震荡」，也不如按频率随机。

### 1.4 中性带有两套互不相干的定义

- 前端/写库的 `direction` 用**概率带**：`upProbability >= .56 ? 'up' : <= .44 ? 'down' : 'flat'`（`server.mjs:2177`）。
- 而「震荡」的物理定义应该是**收益幅度**（`|r| ≤ θ`）或**成本可覆盖的幅度**。

两套定义不统一 → 概率带里的 flat 与实际震荡不是一回事。θ 目前散落在三重屏障的 `1.15σ` 里，既不可配置，也没有在 UI 上展示。

### 1.5 训练标签与结算标签口径不一致

- 训练 `y`：三重屏障**路径**标签（先看哪边被触及）。
- 结算 `is_up`：**终点**收益符号。

实测不一致率：15m **3.0%**、1h **5.9%**、4h **6.4%**。
模型优化的目标和验证它用的目标不是同一个东西 —— 在「准确性验证」这个定位下，这是必须先统一的。

## 二、宏观新闻与宏观日历：数据基建完全缺位

### 2.1 现有三个源，没有一个能直接用于训练

| 源 | 位置 | 实测跨度 | 问题 |
|---|---|---|---|
| `fed_calendar_snapshots` | 表 287，`fedCalendar()` 1299 | **8.37 天** | 只存事件时间；CPI / 非农的 `is_fallback = 1` → **是按月度节奏估算的日期，不是官方确认值** |
| `macro_market_snapshots` | 表 282，`fedMarketSignals()` 1323 | **19.28 天**（DXY/黄金）、**10.32 天**（VIX/WTI） | 只有当前值与日涨跌，19 天 < 一个 CPI 周期 |
| `investmentCalendar` | 1754 | 不落库 | 有 `actual / estimate / previous`（东方财富 + TradingView + FinanceCalendar），但**只保留 `now − 4 天` 之后**，每次实时抓取，无历史 |

已结算预测的时间跨度也只有 **19.2 天**。

### 2.2 宏观在模型里的实际权重是 0

`researchOutlook`（`server.mjs:2148-2190`）：

- `calendar` 只用于 ① `eventRisk`（24h 内事件名，仅展示）② `eventRangeMultiplier = 1.35`（**只放大区间宽度，不改变方向概率**）。
- `macro` 只取 DXY，且返回值里明确写着：`status: 'DXY is displayed for context only until time-aligned history is validated.'`
- 加息 / 降息、CPI 同比意外、非农超预期 —— **对涨跌方向的影响目前是 0**。
- `investmentCalendar`（更全的宏观日历，含各国 CPI / 非农 / 央行决议 / 重要性）**研究模块根本没调用**。

### 2.3 缺的不是代码，是「事件结果库」

宏观要入模，正确的特征编码是**意外值**（surprise = actual − estimate），而不是事件本身。现在：

- `fedCalendar` 只有非农的 actual（且来自 BLS 月度差分），**没有 estimate**；
- `investmentCalendar` 有 estimate 但不落库、不留历史；
- 没有任何地方把「事件时刻」与「BTC 在该事件前后的收益」配对存储。

需要新建 `macro_event_outcomes`：

| 字段 | 说明 |
|---|---|
| `event_key` / `event_at` | cpi / payrolls / fomc / pce / gdp … |
| `actual` / `estimate` / `previous` | 公布值、预期值、前值 |
| `surprise` / `surprise_z` | 原始意外值与标准化意外值 |
| `btc_return_1h_before` / `_1h_after` / `_4h_after` / `_1d_after` | 事件前后 BTC 收益 |
| `source` / `is_fallback` | 来源与是否为回退估算 |

回填路径（免密钥公开源）：
- CPI：BLS 时间序列（如 `CUSR0000SA0` / `CUUR0000SA0`）可拿多年月度值；
- 非农：已有 `payrollReleaseActual()`（BLS `CES0000000001` 月度差分）；
- FOMC 决议：官方日程 + 会议声明，可整理历史决议日期与利率变化；
- BTC 反应：用已有的 `candles`（coinbase 15m，2589 根；日线需先解冻）对齐计算。

**回填必须遵守 point-in-time**：只能使用事件当时可得的值，不能用后来修订的数据，否则验证结果会系统性偏乐观。

## 三、实时对比验证：现有机制的三处失真

| 问题 | 证据 | 后果 |
|---|---|---|
| 采样与结算都由 HTTP 请求驱动 | 写库在 `researchOutlook()` 内（`2185`）；15m 桶覆盖 **20.4%**（1850 个桶只落 378 行），相邻步长 15/30/45/60/75/90 分钟 | 样本是「有人打开页面」的便利样本，不是连续序列 |
| `INSERT OR IGNORE` 只保留首次写入 | `server.mjs:382` | 同一 15 分钟桶内后续访问不会更新概率 → 记分卡上的概率是**该桶第一次被访问时**的输出，不是最新模型 |
| `bucket_at` 与实际决策时刻错位 15 分钟 | 实测：bucket 17:15 的 `entry_price = 81745.30`，而该 K 线最终收盘 81506.50（差 0.293%）。原因是 entry 取「正在形成的那根 K 线的 close」，而 bucket 标的是这根 K 线的起点 | 时间戳与宏观事件对齐会整体偏 15 分钟；收益率混入未收盘噪声 |

另外：结算依赖 `candles.find(c => c.time >= target_at)`，而日线冻结在 2026-08-31 → **1d 预测永不结算**（全库 1d 仅 1 行、0 条已结算），四个周期里 1d 完全无法验证。

## 四、v1 结论在新定位下的重新分级

| v1 结论 | v2 定位下 | 说明 |
|---|---|---|
| 成本后净收益 / 最大回撤 / 保本命中率 | **降级 P2** | 研究平台不执行交易；保留作为参考，但**不应再作为候选升级门槛** |
| 重叠持仓复利放大（1h 2.1×、4h 12.5×） | **降级 P1** | 评估准确率时重叠样本主要影响置信区间；主口径改为非重叠，重叠作为副口径 |
| 日线冻结 → 1d 死锁 | **保持 P0** | 你要验证四个周期，1d 现在是 0 样本 |
| 采样由访问驱动 | **升为 P0** | 准确性验证需要连续、无偏的样本 |
| 缺「不交易」对照 | **替换为 P0**：缺「永远猜震荡 / 随机」对照 | 这才是研究口径的正确基线 |
| OI 交互项优先级 bug（`2152`） | **保持 P1** | `(Number(x)\|\|0>=0?1:-1)` 恒为 1，已实测 |
| A/B 升级门槛用经济指标 | **升为 P1** | 必须改为三分类准确率 + 校准 + Brier Skill |

## 五、推荐修复顺序

### 阶段 0 · 让数据先连续（无模型改动，纯基建）

1. **`forecastHistory` 加时效判据**（`server.mjs:1927`）：把 `stored.length >= 900` 改为按末根 K 线时间判断新鲜度，日线按「超过 1 个日线周期」回源。
   - 验收：`candles` 表 `coinbase/1d` 最后一根回到当天；`research_predictions` 里 1d 开始产生并结算。
2. **预测采样与结算挪到服务端定时器**（脱离 HTTP 请求）：每 15 分钟生成四周期预测，每 15 分钟尝试结算到期预测。
   - 验收：连续 24 小时后，15m 桶覆盖率 > 95%，相邻步长恒为 15 分钟。
3. **`bucket_at` 与 entry 对齐**：entry 固定取「已收盘的最后一根 K 线的 close」，bucket_at 用该 K 线时间，不再取整漂移。
   - 验收：`entry_price` 与 bucket 对应 K 线收盘价完全一致（差 0）。
4. **顺手修**：OI 优先级 bug（`2152`）；进度文案「1119/120」；`INSERT OR IGNORE` 改为按 `(bucket_at, horizon_key)` 更新未结算行。

### 阶段 1 · 三分类地基（核心，必须先于宏观）

5. **统一标签定义**：新增 `outcome_label`（up / flat / down）与 `theta` 字段写入 `research_predictions`；θ 由波动 × 系数（并按周期可配置）定义，**UI 上明确展示 θ 数值**。
6. **统一训练标签与结算标签**：`tripleBarrier` 的 vertical 分支不再强制二值化，而是产出第三类；或改为「先判震荡、震荡之外再判方向」的两阶段标签。
   - 验收：训练标签与结算标签不一致率 = 0。
7. **记分卡改三分类**：输出混淆矩阵、三分类准确率、每类精确率/召回率、**漏报率**，并固定展示三条基线（永远猜震荡 / 按频率随机 / 上一版本）。
   - 验收：页面上能直接读出「模型比永远猜震荡高/低多少 pp」。
8. **`direction` 判定改为收益口径**：由概率带改为「预测分布落在 ±θ 之外的概率质量」或 EV 门槛，与 θ 保持一致。

### 阶段 2 · 宏观数据基建

9. **建 `macro_event_outcomes` 表 + 回填**：CPI / 非农 / FOMC / PCE，至少回填 24 个月，记录 actual / estimate / previous / surprise 与 BTC 前后 1h / 4h / 1d 收益，全部 point-in-time。
   - 验收：CPI ≥ 24 条、非农 ≥ 24 条、FOMC ≥ 8 条历史记录，且每条都有 BTC 前后收益。
10. **事件落库常态化**：`investmentCalendar` 每次刷新时把 `actual / estimate / previous` 落库（它现在只保留 4 天窗口且完全不落库），事件到期后自动补齐 BTC 反应。
11. **宏观特征工程**（point-in-time 对齐，写入预测行）：距下次事件小时数、事件后小时数、标准化 surprise、事件重要性、DXY/VIX 变化。
    - 验收：每条预测行都能查到当天的宏观特征快照，且不含任何未来信息。

### 阶段 3 · 宏观入模与消融验证

12. **先做可解释的事件窗口效应**：事件窗口内波动放大（现有 1.35× 固定值改为按事件类型与 surprise 标定）、方向偏移按 surprise 符号与历史回归系数给出。
13. **消融实验**：对比「不含宏观特征」与「含宏观特征」的三分类准确率、Brier Skill、ECE，**差异必须给出置信区间**。
14. **A/B 升级门槛改为三分类指标**（`compareCandidateToBaseline` 2093 的 economics 门槛替换）。
    - 验收：升级门槛文案与页面上展示的指标一致。

### 阶段 4 · 治理与文档

15. 权重参数（新闻 0.25/0.12、analogueWeight、logit 位移 0.22/0.12/0.18、treeWeight）外置为配置并序列化入库，使每次预测可追溯「当时用的是哪套权重」。
16. 前端新增「宏观因子贡献」区块：展示当前生效的宏观事件、surprise、对概率的净影响。
17. 补齐 `docs/预测与计算说明.md` 的研究预测章节（目前完全没有这一章）。
